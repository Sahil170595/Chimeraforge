# Kubernetes inspection field-domain protocol evidence

This is editable-source controlled protocol evidence for unreleased 0.85.0,
not installed-distribution, native kubectl/kind, inference or GPU qualification.
[summary.json](summary.json) records the actual timestamp, control rows, owned
process count, source-byte preservation, raw CLI byte parity and source hashes.
It contains no config/resource bodies, credential values or runtime input paths.

Regenerate from the repository using the existing development environment:

```bash
python scripts/ci_kubernetes_inspection.py \
  --record validation/2026-10-31-kubernetes-inspection/summary.json --checkout .
```

The native planner emits original N3 candidates for both supported engines.
Controlled responses travel through real owned Python subprocess pipes and the
actual API/in-process CLI; a separate actual module CLI checks raw missing-tool
stdout bytes. Matching status, drift, pending status, missing Service, unsupported
provider, wrong identity, malformed condition text and out-of-domain generation
and replica counters retain all six resources and ten declared JUnit cases.
Completed private inventory permits paired API/CLI files; incomplete inventory
must refuse all requested files while bounded stdout and typed outcomes remain.
The selected fictional native client is also protected from delayed API writes
and CLI output aliases before any launch. This exercises the input-file role
with controlled Python protocol processes, not a real kubectl binary.

The condition and integer controls establish conservative admission of the
used native field domains. They do not claim a general OpenAPI validator or
universal Go conversion overflow rejection. The earlier
[October 30 record](../2026-10-30-kubernetes-inspection/README.md) remains a
separate historical source snapshot with its original controls and hashes.

The existing installed consumer runs this same protocol against each actual
wheel/rebuilt-sdist package with all-loaded-module origin checks. Native pinned
tool syntax, genuine GPU-declaration/pending-rollout4, restricted authentication,
credential-policy and legacy-home migration controls remain separate hosted
kind requirements. Pure status 0 is not a real GPU-ready result.

The [second hosted attempt](https://github.com/Sahil170595/Chimeraforge/actions/runs/41170495376/job/124447275639)
passed both engines' native inspection and preceding adverse controls, then
failed an explicit-context fixture that used an empty user as static auth.
Its exact selected-report reason was not retained. Pinned kubectl source shows
that an empty user can prompt before transport with closed stdin. The fixture
now retains that negative, privately checks the native prompt, and uses an
explicit fictional static bearer for the positive API/CLI context controls.
Only categorical counts of matching authenticated version GETs are retained;
fresh hosted execution must establish these outcomes.
